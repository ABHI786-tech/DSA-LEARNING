0x00Foundations

Introduction to DSA

Data Structures and Algorithms (DSA) is the study of how to organize data so it can be used efficiently, and how to write step-by-step procedures that act on that data to solve a problem.

The two halves are inseparable. A data structure is the container — an array, a list, a tree — that decides how information sits in memory. An algorithm is the recipe that walks through that container to search, sort, insert, or transform what's inside it. Pick the wrong container, and even a clever recipe runs slow; pick the right one, and simple recipes fly.

Learning DSA is really learning a small vocabulary of containers and a small vocabulary of moves, then recognizing which pair fits the problem in front of you.

0x01Why it matters

Importance of Data Structuring

Raw, unorganized data is slow to work with — finding one record in a random pile means checking everything. Structuring data trades a little setup effort for a lot of speed and clarity later.

What good structuring buys you
  • Efficiency — faster search, insert, and delete instead of scanning everything
  • Memory management — data is stored and reused without waste
  • Scalability — the same design keeps working as data grows into millions of records
  • Reusability — a well-defined structure can back many different algorithms
  • Real-world modelling — trees for file systems, graphs for maps, queues for task scheduling
0x02Taxonomy

Classification of DSA

Data structures split first by whether the language gives them to you built-in, then by how their elements relate to each other in memory.

Primitive structures — int, float, char, boolean — hold a single raw value. Non-primitive structures are built from primitives and are further split into:

Linear — elements sit one after another in a sequence (array, stack, queue, linked list). Non-linear — elements branch or connect in multiple directions (tree, graph, hash map).

0x03Linear structures

Array & List

An array is a fixed-size block of memory where every element sits right next to the last, so any element can be reached instantly using its index.

A list (as in Python's list or Java's ArrayList) looks similar on the surface but resizes itself automatically as items are added or removed, trading a little overhead for flexibility.

0x04OOP building block

Classes

A class is a blueprint. It doesn't hold any real data itself — it describes what attributes (data) and methods (behaviour) every object built from it will have.

In DSA, classes are how structures like linked lists, stacks, and trees actually get built in code — a Node class, a LinkedList class, and so on.

Example
class Car:
    def __init__(self, brand, speed):
        self.brand = brand
        self.speed = speed

    def accelerate(self):
        self.speed += 10
0x05OOP principle

Encapsulation

Encapsulation means bundling data and the methods that operate on it inside one unit — the class — and controlling what the outside world is allowed to touch directly.

Fields are often marked private, and access is only given through defined methods (getters/setters). This keeps a structure's internal state — like a linked list's head pointer — safe from being corrupted by outside code.

Example
class Account:
    def __init__(self, balance):
        self.__balance = balance  # private

    def get_balance(self):
        return self.__balance
0x06OOP building block

Object

An object is a real, living instance of a class — the class is the blueprint, the object is the house actually built from it. Each object has its own state (values in its attributes), behaviour (methods it can run), and a unique identity in memory.

Every node in a linked list, every element pushed onto a stack — these are all objects created from a class.

Example
my_car = Car("Toyota", 0)
my_car.accelerate()
# my_car is an object — a concrete Car
0x07Linear · dynamic

Singly Linked List

A singly linked list is a chain of nodes where each node points to the next one. Unlike an array, its elements are not stored next to each other in memory — they're scattered, and held together purely by pointers.

The list itself only needs to remember one thing: the head, the address of the first node. From there, you follow the chain of next pointers to reach everything else.

0x08The atomic unit

What is a Node

A node is the basic building block of a linked list. Every node bundles two things: the data it holds, and a pointer (or reference) to the next node in the chain.

A node knows nothing about the list as a whole — it only knows its own value and who comes after it. That local simplicity is what lets long chains be built, split, and rearranged just by changing a few pointers.

Node class
class Node:
    def __init__(self, data):
        self.data = data   # the value
        self.next = None  # pointer to next node
0x09Working with the chain

Operations of the Singly Linked List

All singly linked list operations come down to reading or rewiring the next pointers.

Core operations
  • Traversal — start at head, follow next until reaching null, visiting every node once
  • Insertion — at the head, at the tail, or in the middle, by pointing a new node's next at the right place
  • Deletion — skip a node by pointing its predecessor's next straight to its successor
  • Search — traverse while comparing each node's data to a target value
Time complexity
OperationBestWorst
Insert at headO(1)O(1)
Insert at tailO(1)*O(n)
Delete a nodeO(1)O(n)
Search / traverseO(1)O(n)

*O(1) only if a tail pointer is kept; otherwise O(n) to reach the end.

0x0ALinear · dynamic

Doubly Linked List

A doubly linked list gives every node a second pointer, prev, alongside next. That means the chain can be walked in both directions — forward from the head, or backward from the tail.

The trade-off: each node spends a little extra memory on that second pointer, and every insertion or deletion has two links to update instead of one. In exchange, operations like "delete this node" or "go to the previous item" no longer require re-traversing the whole list from the start.
